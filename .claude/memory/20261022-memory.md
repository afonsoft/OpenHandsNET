## Findings — chrome-devtools-mcp no sandbox

Mecânica: MCP stdio roda via `docker exec -i <container>` dentro do sandbox
(McpClientService.ResolveStdioAsync); host bloqueado sem `Mcp:AllowHostMcp`.
Imagem runtime: ubuntu24.04 + node22 + user `openhands` (non-root — requisito:
Chrome recusa root). Falta Chrome + deps de SO.

Config recomendada (stdio in-sandbox):
`npx -y chrome-devtools-mcp@latest --headless --isolated --chrome-arg=--no-sandbox`
- `--no-sandbox` necessário em docker comum (sem userns); sob sysbox (k8s)
  pode omitir. `--isolated` evita "Target closed" (issue #131).
- Chrome via custom image (docs/deployment/custom-images.md) — sugestão:
  installer `/opt/ohn/sdks/chrome.sh` seguindo o padrão sdk blueprint.
- Alternativa: `--browser-url=http://<ip>:9222` — **Host header deve ser IP**
  (Chrome rejeita hostname como host.docker.internal); socat/ssh -L p/ 127.0.0.1
  (padrão chrome-wsl, que suporta `--container=<name>`); em k8s, sidecar no
  mesmo pod → 127.0.0.1:9222 direto.
- Egress: allowlist precisa registry.npmjs.org (ou `npm i -g` baked na imagem);
  `--no-usage-statistics` / `CHROME_DEVTOOLS_MCP_NO_USAGE_STATISTICS=1` e
  `--no-performance-crux` para não vazar telemetria/CrUX.
- `mcp__chrome-devtools__*` cai no piso MCP do security_policy (balanced passa,
  strict exige confirmação); `RequireConfirmation` por servidor existe.
