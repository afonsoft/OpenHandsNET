## Sessão 2026-11-10 (cont. 3) — SPEC-141 CI autofix loop

## Prompts
- "SPEC-141 CI Autofix Loop" (issue #406): webhook check_run/workflow_run
  em PR inscrito → run autofix (logs bounded+redacted → classificação →
  conversa agent_type=autofix → push na branch do PR → poll → verde ou
  cap 3). Estudar SPEC-140 merged antes (padrões webhook/runner/

## Checkpoints / Decisões
- Branch `feature/spec-141-ci-autofix`. Stack completa implementada:
  `AutofixContracts` (statuses/CiCheckEvent/ScmCheckRun/records/service),
  `AutofixOptions` (Autofix:*), `CiCheckEventParser` (4 event types →
  evento normalizado), `CiFailureClassifier` (lint|type|test|build
  fixáveis; infra|timeout|flaky|permissão|segredo → blocked sem
  consumir tentativa), `AutofixService` (policy: falha, own check/app/
  ator bot, check-name glob conexão→global, PR resolve payload→
  commits/{sha}/pulls→conversations.PullRequestHeadSha, AutofixCovers,
  fork-block, anti-loop por head_sha_out, dedup head+check + 1 ativo/PR,
  quota diária), `AutofixDispatcher`+`AutofixRunWorker` (paralelo —
  runs poll longos), `AutofixRunner` (fetch log → classify → attempt+
  conversa de fix → poll push+checks → green/red cap/timeout/pr closed/
  cancel; status `sandcastle/autofix` advisory; comentários
  success/give-up/blocked/error; audit scm.autofix_triggered|
  _attempt|_completed|_failed).
- Provider: `IScmProvider` +4 (GetCheckRuns, GetCheckRunLogs,
  GetWorkflowRunLogs(zip→txt), GetPullRequestsForCommit); REST providers

  `IGitService.ProvisionTokenAuthAsync` + `IGitHubClientFactory.
  GetInstallationTokenAsync` — push c/ installation token da conexão.
- Persistence: `scm_connections.autofix_{enabled,repos_json,
  check_patterns_json,max_attempts}` + `autofix_runs` +
  `autofix_attempts` — migrations SQLite `20261110194737` e Postgres
  `20261110194846` (`dotnet ef --startup-project src/Sandcastle.Api`).
- API: `POST /scm/autofix` (manual, 202+{autofix_run_id}), GET
  `/scm/autofix-runs` (repo/pr/status+cursor), `GET /scm/autofix-runs/
  {id}` (run+attempts), `POST …/cancel`; PATCH connections aceita
  `autofix_*` no mesmo `ScmConnectionReviewPatch`.
- Admin: coluna toggle `admin.scm_autofix` em AdminScmPage +
  `PatchScmConnectionAutofixAsync` + 3 chaves i18n ×8 locales.
- Tests: `Spec141AutofixTests` (40) — parser 4, webhook routing 3,

  ganharam os 4 membros novos de IScmProvider + ProvisionTokenAuthAsync.

## Erros / retrabalho
- `IReadOnlySet<string>.Contains` não traduz no EF (SQLite) →
  `AutofixRunStatuses.Active` virou `string[]` (IN clause + in-memory).
- Octokit: `client.Connection.Get<T>` → `IApiResponse<T>` — precisa
  `.Body` (commits/{sha}/pulls não tem helper tipado).
- `UntrustedInput` está em `Infrastructure.Security` (não `.Agent`);
  `SecretRedactor` em `Infrastructure.Agent` — ambos necessários no
  Formatter.
- `$$"""` raw-string quebra com `}}`/`}}}` de JSON → payloads de teste
  em concat plain.
- `dotnet ef migrations add` exige `--startup-project src/Sandcastle.Api`
  (Infra não referencia EF.Design).

## Lições
- `AutofixRunWorker` despacha runs em tasks paralelas (não sequencial
  como ReviewRunWorker) — poll de checks pode durar 45min/run.
- Infra/timeout/flaky/permissão/segredo nunca consomem tentativa nem
  criam conversa — bail-out `blocked` + comentário + status error.
- Poll interno (PR head mudou → checks terminais no head novo) evita
  depender de webhook do próprio push; `head_sha_out` guarda anti-loop.
